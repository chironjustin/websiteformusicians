# Security Notes

- Frontend code uses only `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
- No Supabase service-role key is present or required.
- Admin routes are protected by Supabase Auth in the React app.
- The `events` table has Row Level Security enabled in `supabase/schema.sql`.
- Public reads are limited to `upcoming`, `live`, and `finished` events. Draft events are not publicly readable.
- Insert, update, and delete policies require `owner_id = auth.uid()`.
- Storage paths are scoped by user ID and event ID.
- Image buckets are intended to be public; the audio bucket is intended to remain private.
- Audio playback uses signed URLs generated by the anon client under storage policies.
- File uploads validate supported image/audio MIME types and size limits before upload.
- Admin URL fields are validated to require `http:` or `https:`.
- Chat messages render as plain text, are trimmed, and are limited to 500 characters.
- Visitor chat inserts are pending by default. Public users can read approved messages only and cannot set moderation fields through RLS.
- Admin chat moderation is restricted to the owner of the related event through `supabase/chat-schema.sql`.
- Supabase error messages are surfaced in the admin UI for debugging. For a fully polished public launch, consider mapping raw backend messages to friendlier copy.
- Fully reliable automatic status transitions are not implemented in the frontend. Use a trusted scheduler such as Supabase scheduled Edge Functions, Supabase Cron, or a scheduled Vercel Function for automatic database writes.
